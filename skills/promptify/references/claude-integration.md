# Anthropic integration notes

Use only when the user asks for API, configuration, or migration notes, and keep them outside copyable prompt text. Rules apply only to the named model. For a dated offline disclosure, cite the target's Reviewed date in [Claude families](claude-families.md).

## Claude Fable 5.2

[What's new](https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2) and the [migration guide](https://platform.claude.com/docs/en/models/fable-5-2/migration-guide) specify always-on adaptive thinking: `disabled` and manual `enabled`/`budget_tokens` return a 400 error. Assistant prefill, non-default sampling parameters, and forced `tool_choice` values `any` and `tool` also fail. Use `auto` with explicit tool triggers and strict tools, or JSON outputs. Neither strict tools nor JSON outputs are available in organizations with customer-managed encryption keys.

Effort defaults to `high`; start there and rerun the sweep rather than carrying over a Fable 5.1 or Opus 5.5 setting. `medium` suits interactive coding and chat, `low` suits quick, well-specified, high-volume work, `xhigh` is for measured gains on the hardest work, and `max` is for measuring the ceiling. Thinking counts toward `max_tokens`, so a small value can stop after a thinking block with no text.

Keep history append-only. The prefix check applies to every account: resending thinking blocks after editing `system`, `tools`, or an earlier message returns a 400 error by default. Use context editing or compaction to shorten history. `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` with beta header `thinking-binding-controls-2026-08-01` is a stopgap that can raise output tokens. On the Claude API and Google Cloud, Fable 5.2 reads blocks from Opus 5.5, Sonnet 5.5, Haiku 5.5, Fable 5.1, and earlier models. Only Fable 5.2 and Mythos 5.2 read its blocks, so moving to any other model drops that reasoning while the request still succeeds. Blocks work only in the producing or a linked account. See [preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking).

Replace `computer_20251124` with `computer_toolset_20260801` everywhere except Amazon Bedrock. A Fable 5.2 executor needs a Fable 5.2 or Mythos 5.2 advisor. Updates between tool calls arrive in `thinking` blocks, empty at the default `display: "omitted"`; use `display: "updates"` with `thinking-display-updates-2026-08-18`, or `"summarized"`. Prompting for updates alone does not make a client render them.

## Claude Opus 5.5

[What's new](https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5) and the [migration guide](https://platform.claude.com/docs/en/models/opus-5-5/migration-guide) specify always-on adaptive thinking: omit `thinking` or use `type: "adaptive"`; `disabled` and manual `enabled`/`budget_tokens` fail. Effort supports `low`, `medium` (default), `high`, `xhigh`, and `max`. Evaluate from `medium`, or `low` when replacing a thinking-disabled workflow; leave room in `max_tokens` for thinking plus the response.

Forced `tool_choice` values `any` and `tool` fail. Use `auto` with explicit tool triggers and strict tools, or Structured Outputs for a schema; strict tools do not force a call. Assistant prefill and non-default sampling parameters are rejected. On the Claude API and Google Cloud, replace `computer_20251124` with `computer_toolset_20260801` and update the tool-result loop per the migration guide. Amazon Bedrock still accepts the earlier computer tool; verify other platforms separately.

Replay full assistant turns and thinking blocks unchanged. Prefix binding is enforced by default for accounts created on/after 2026-08-31 and when older accounts opt in; editing prior messages, system instructions, or tools can invalidate later blocks. Use supported append-only changes or server-side context management. Model-switch compatibility is directional: Opus 5.5 reads earlier Opus/Sonnet/Haiku blocks and, on the Claude API and Google Cloud, Sonnet 5.5 and Haiku 5.5 blocks; it does not read Fable/Mythos blocks. Fable 5.2 reads Opus 5.5 blocks on the Claude API and Google Cloud. Consult [preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking) instead of blanket-stripping history.

Intermediate progress arrives in `thinking` blocks, whose text is empty at the default `display: "omitted"`. To render progress summaries, use `thinking.display: "updates"` with `thinking-display-updates-2026-08-18` and parse blocks by `type`. Asking for progress in a prompt does not fix a text-only renderer. See [progress updates](https://platform.claude.com/docs/en/build-with-claude/thinking#progress-updates).

## Claude Sonnet 5.5

[What's new](https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5) and the [migration guide](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide) specify adaptive thinking on by default and effort default `high`. Effort levels are recalibrated: rerun an effort sweep rather than carrying over Sonnet 5 settings. Start agentic coding at `medium` (`high` for harder or longer tasks) and chat or latency-sensitive work at `medium` or `low`. Leave room in `max_tokens` for thinking plus the response.

`disabled` and manual `budget_tokens` fail. The lowest setting is `thinking: {"type": "between_tools"}`, accepted only at `high` effort or below, with no `display`, `budget_tokens`, or `block_binding` field and no per-message effort change. Without tools it answers without thinking, so use adaptive thinking for reasoning tasks. Forced `tool_choice` values `any` and `tool`, assistant prefill, and non-default sampling parameters fail. Use `auto` with explicit tool triggers and strict tools, or Structured Outputs; strict tools do not force a call. With Structured Outputs, treat `stop_reason: "max_tokens"` as a failed response.

Replay full assistant turns and thinking blocks unchanged and keep history append-only. Prefix binding is enforced by default for accounts created on/after 2026-08-31 and when older accounts opt in with adaptive thinking; editing prior messages, system instructions, or tools can invalidate later blocks. Sonnet 5.5 blocks also work only in the producing or a linked account. It reads Sonnet 5, Opus 4.8, Haiku 4.5, and earlier blocks, plus Haiku 5.5 blocks on the Claude API and Google Cloud; not Opus 5/5.5, Fable, or Mythos blocks. Only Opus 5.5 and Fable 5.2 read its blocks, on the Claude API and Google Cloud; switching to any other model drops that reasoning. See [preserved thinking](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking). On the Claude API and Google Cloud, replace `computer_20251124` with `computer_toolset_20260801`. Advisor-tool pairings changed; check the advisor compatibility list.

Notes between tool calls longer than a sentence or two arrive in `thinking` blocks, empty at the default `display: "omitted"`; shorter remarks stay `text`. Render it with `thinking.display: "updates"` and `thinking-display-updates-2026-08-18` under adaptive thinking; `between_tools` returns the text without a `display` field. Deliver mid-turn user input as user text after the last `tool_result`, never inside one; otherwise the model can treat it as injected text.

## Claude Haiku 5.5

[What's new](https://platform.claude.com/docs/en/models/haiku-5-5/whats-new-haiku-5-5) and the [migration guide](https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide) specify adaptive thinking on by default and effort `low` through `max`, default `medium`. Effort, not prompt text, controls thinking: start at `medium`; use `low` for chat, short tool tasks, and simple high-volume requests, but `high` for knowledge work, longer agent tasks, and chatbots where strict system-prompt adherence matters most; compare `xhigh`/`max` against Sonnet 5.5. `thinking: {"type": "disabled"}` works only at `high` or below. At `xhigh` in multi-turn chat, check for empty visible replies. Thinking counts toward `max_tokens`; size it for thinking plus the response.

Manual `budget_tokens`, assistant prefill, non-default sampling parameters, and `computer_20250124` fail. Replace prefill with Structured Outputs or a tool with an enum for constrained output. Use `computer_toolset_20260801` on the Claude API and Google Cloud, or `computer_20251124` on Amazon Bedrock. Forced `tool_choice` is accepted but skips thinking before the call; prefer `auto` with explicit tool triggers. Thinking text is omitted by default; set `display: "summarized"` to receive it. Safety classifiers can return `stop_reason: "refusal"` with no server-side fallback, so handle refusals in the client.

Replay full assistant turns and thinking blocks unchanged and keep history append-only; prefix binding applies as for Sonnet 5.5, and blocks work only in the producing or a linked account. Add new system-prompt text to new conversations only, or put changed instructions in the newest turn. Likewise, render a date placeholder once when the conversation starts; on a later day, give the new date in the newest turn rather than re-rendering `system` or tool descriptions. It reads Sonnet 5, Opus 4.8, Haiku 4.5, and earlier blocks; Opus 5.5, Sonnet 5.5, and Fable 5.2 read its blocks on the Claude API and Google Cloud. Deliver mid-turn user input as user text after the last `tool_result`, never inside one.

## All models

For changing effort during a conversation, the [per-message effort beta](https://platform.claude.com/docs/en/build-with-claude/effort#change-effort-mid-conversation) supports Fable 5.2, Opus 5.5, Opus 5, Sonnet 5.5, and Haiku 5.5 on the Claude API and Google Cloud; on Amazon Bedrock, only Fable 5.2 and Opus 5.5. It needs adaptive thinking on Sonnet 5.5 (not `between_tools`) and Haiku 5.5 (not `disabled`). With beta header `mid-conversation-output-config-2026-07-01`, append a `role: "system"` message with empty `content` and `output_config.effort`; it applies from the next user turn while preserving the cached prefix. This is client configuration, not an instruction to think harder. Verify support before applying this mechanism to another model.

In this reference, "Google Cloud" means Claude Models on Google Cloud (Google managed). The Anthropic-managed Google Cloud offering (2026-10-22) is separate; verify its feature support before applying platform-specific notes.

API version `2026-10-21`, the default in current SDKs, rejects `temperature`, `top_p`, and `top_k` on every model, even at their defaults. Integration notes should omit them rather than only resetting them to defaults. See [the migration guide](https://platform.claude.com/docs/en/api/migration-2026-10-21).

The [thinking](https://platform.claude.com/docs/en/build-with-claude/thinking) and [effort](https://platform.claude.com/docs/en/build-with-claude/effort) references govern API controls. Effort is not a word budget, and `max_tokens` includes thinking plus response text. Prefill, tool choice, thinking display, and replay rules differ by model.

Promptify does not maintain pricing, retention, beta-support, or platform-tool matrices. Fetch the exact capability docs when needed. Model intelligence does not prove that a tool is installed or supported: hosted [web fetch](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool), for example, has its own support list.
